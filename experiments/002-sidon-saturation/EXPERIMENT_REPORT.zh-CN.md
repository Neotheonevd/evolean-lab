# EvoLean Lab 实验记录 002：极小的极大 Sidon 集

## 1. 实验摘要

本实验测试 EvoLean Lab 是否能够完成一个最小但完整的数学研究闭环：从经典问题附近选择一个可计算的子问题，生成猜想，主动寻找反例，修正猜想，建立独立验证，并使用 Lean 核验其中可形式化的部分。

实验得到以下精确有限结论候选：

> 设 `s(N)` 是区间 `[1,N]` 中按包含关系极大的 Sidon 集的最小大小，则
>
> `s(43) = 6`。

当前证据状态如下：

- `s(43) ≤ 6`：已经由 Lean 对具体六元素见证进行机械核验，状态为 `VERIFIED`。
- `s(43) > 5`：已经由独立的穷举程序检查所有大小不超过五的子集，状态为 `COMPUTATIONALLY_VERIFIED`。
- 完整等式尚未成为纯 Lean 定理，因为百万规模的穷举下界还没有转换为 Lean 可检查的证明证书。
- 结果的新颖性尚未确认。一般研究方向已有文献，因此不得把本实验直接称为新数学成果。

## 2. 背景与动机

实验 001 研究了经典函数 `F(N)`：区间 `[1,N]` 中 Sidon 子集的最大大小。精确搜索很快重新发现了最优 Golomb ruler 数据。这证明了计算与 Lean 管道能够工作，却没有产生新的数学方向。

为了寻找一个更适合 agent 探索的问题，本实验把“最大大小”改为“极小饱和大小”。这种转换在极值组合数学中很常见：

- 极值问题问一个合法对象能够有多大；
- 饱和问题问一个已经无法继续扩张的合法对象能够有多小。

它保留了 Sidon 集的经典结构，同时产生了新的搜索目标、局部阻塞机制和潜在的上下界问题。

## 3. 数学定义

### 3.1 Sidon 集

有限集合 `A ⊆ ℕ` 称为 Sidon 集，如果任意两个非降序元素对的和都唯一。也就是说，若

`a,b,c,d ∈ A`、`a ≤ b`、`c ≤ d`，并且

`a + b = c + d`，

则必有

`a = c` 且 `b = d`。

对于整数集合，这等价于所有不同元素对产生的正差互不相同。因此 Sidon 集也可以看作 Golomb ruler 的整数版本。

### 3.2 按包含关系极大

给定 `A ⊆ [1,N]`，如果：

1. `A` 是 Sidon 集；
2. 对任意 `x ∈ [1,N] \ A`，集合 `A ∪ {x}` 都不再是 Sidon 集；

则称 `A` 是 `[1,N]` 中按包含关系极大的 Sidon 集。

这里的“极大”不等于“最大”：

- 最大 Sidon 集具有区间内最大的可能基数；
- 极大 Sidon 集只要求不能再加入元素，其大小可能远小于最大值。

### 3.3 饱和函数

定义

`s(N) = min {|A| : A 是 [1,N] 中按包含关系极大的 Sidon 集}`。

本实验的目标是计算小规模 `s(N)`，寻找规律，并尝试得到一个完整可验证的有限结论。

## 4. 实验设计

实验由四个相互区分的阶段组成：

1. 使用元素对之和定义 Sidon 性质，穷举小区间中的极小极大集；
2. 根据数值序列生成候选规律；
3. 用更大规模的固定阶搜索主动攻击候选规律；
4. 分别使用 Lean 的“和”模型与 Python 的“差”模型核验最终候选。

将“和”与“差”分开实现非常重要。如果两个验证器复制了同一段判断逻辑，那么一致结果可能仅仅意味着它们共享同一个错误。

## 5. 第一阶段：生成小规模数据

`saturation_scan.py` 枚举 `[1,N]` 中的 Sidon 子集，并检查其是否按包含关系极大。

程序获得的前若干值为：

| `N` 的范围 | `s(N)` |
|---|---:|
| `N = 1` | 1 |
| `2 ≤ N ≤ 4` | 2 |
| `5 ≤ N ≤ 10` | 3 |
| `11 ≤ N ≤ 22` | 4 |
| `23 ≤ N ≤ 35` | 5 |

最初的跳跃位置是：

`2, 5, 11, 23`。

换一种说法，大小分别为 1、2、3、4 的 Sidon 集能够饱和的最长初始区间长度为：

`1, 4, 10, 22`。

## 6. 一个诱人但错误的猜想

前三次增长满足递推形式

`M(k) = 2 M(k-1) + 2`，

等价于

`M(k) = 3·2^(k-1) - 2`。

如果继续外推，五元素 Sidon 集应该最多饱和 `[1,46]`，下一次 `s(N)` 跳跃应发生在 `N=47`。

这是典型的“小数据过拟合”：公式简洁，并且完全符合已有数据，却没有结构证明。

本实验没有把该规律直接升级为猜想，而是将其作为优先反驳目标。

## 7. 第二阶段：固定五元素搜索

`fixed_order_scan.py` 枚举坐标不超过 55 的所有五元素 Sidon 集，并计算每个集合能够饱和的最长初始区间。

搜索检查了 2,090,500 个五元素 Sidon 集。得到的最大饱和前缀不是 46，而是 42。

达到 42 的两个见证为：

- `{10,18,19,25,30}`；
- `{13,18,24,25,33}`。

因此，倍增规律被明确反驳。实验从错误猜想转向新的候选结论：

> 五个元素不能饱和 `[1,43]`，但六个元素可能可以。

这一步是本实验最重要的 agent 行为之一：系统没有围绕一个漂亮规律不断寻找支持证据，而是主动分配计算资源寻找反例。

## 8. 第三阶段：寻找六元素见证

`find_witness.py` 搜索 `[1,43]` 中的六元素 Sidon 集，并检查极大性。

在检查 1,097 个六元素 Sidon 候选后，程序找到：

`A = {1,2,4,13,32,37}`。

该集合满足：

1. 所有非降序元素对的和互不相同；
2. 对每个 `x ∈ [1,43] \ A`，向 `A` 中加入 `x` 都会产生重复的元素对之和。

因此它给出上界：

`s(43) ≤ 6`。

## 9. Lean 核验

形式化文件为 `Saturation43.lean`。

Lean 文件定义了：

- 一个列表的所有非降序元素对之和；
- 基于这些和是否无重复的可判定 Sidon 谓词；
- 区间内的可判定极大性谓词；
- 六元素见证 `[1,2,4,13,32,37]`。

Lean 已机械核验以下两个声明：

1. 该见证长度为 6；
2. 该见证在 `[1,43]` 中是极大 Sidon 集。

检查使用本地 Lean 4 与 Mathlib，退出码为 0，并且没有使用：

- `sorry`；
- `admit`；
- 新增公理；
- 弱化后的区间或结论。

因此 Lean 部分的正式状态为：

`VERIFIED: s(43) ≤ 6`。

需要强调，Lean 当前核验的是具体上界见证，而不是整个等式 `s(43)=6`。

## 10. 独立下界验证

为了验证不存在更小的极大 Sidon 集，实验编写了第二个实现 `independent_difference_check.py`。

它不使用元素对之和，而使用等价的正差条件：一个整数集合是 Sidon 集，当且仅当不同元素对产生的所有正差互不相同。

程序完整枚举 `[1,43]` 中大小 1 至 5 的全部子集：

| 大小 | 子集总数 | Sidon 子集数 |
|---:|---:|---:|
| 1 | 43 | 43 |
| 2 | 903 | 903 |
| 3 | 12,341 | 11,900 |
| 4 | 123,410 | 100,814 |
| 5 | 962,598 | 490,164 |
| 合计 | 1,099,295 | 603,824 |

检查结果：这 603,824 个大小不超过五的 Sidon 集中，没有任何一个在 `[1,43]` 中极大。

同一程序还再次确认六元素见证：

- 正差互异；
- 在 `[1,43]` 中极大。

因此计算上得到：

`s(43) > 5`。

结合 Lean 已验证的上界，得到：

`s(43) = 6`。

不过，下界目前仍依赖 Python 穷举。严格状态应写成 `COMPUTATIONALLY_VERIFIED`，不能冒充完整的 Lean 形式证明。

## 11. 可信度与剩余风险

### 11.1 已降低的风险

- 上界和下界采用不同程序；
- 一个实现使用和，另一个实现使用差；
- 六元素见证经过 Lean 编译验证；
- 搜索覆盖了所有大小 1 至 5 的子集，而不只是大小 5；
- 错误的指数规律已经被主动反例搜索淘汰。

### 11.2 尚未消除的风险

- Python 穷举器本身尚未被形式验证；
- 没有生成可由 Lean 小内核逐条检查的下界证书；
- 当前文献搜索不足以确认精确值 `s(43)=6` 是否已发表或收录；
- 单个精确有限值即使新颖，也通常不足以构成论文，除非伴随新算法、新序列、一般定理或有意义的分类结果。

## 12. 文献查重与研究定位

最初的关键词“minimum maximal Sidon subset of an interval”没有立即返回直接答案，但扩大到以下术语后发现了已有研究：

- maximal Sidon set；
- small maximal Sidon set；
- complete Sidon set；
- small complete structures。

2025 年关于 complete 3-AP-free sets 的综述明确指出，小型 complete Sidon 集在整数和有限群中已有研究，并引用：

- I. Z. Ruzsa, *Solving a linear equation in a set of integers I*, 1993；
- I. Z. Ruzsa, *A small maximal Sidon set*, 1998。

因此本实验不能声称发明了该问题。当前合理定位是：

1. `s(N)` 的精确小值可能形成一个可查新、可扩展的数据问题；
2. 更有研究价值的目标是建立一般上下界、构造或结构分类；
3. 本实验首先是 EvoLean Lab 研究流程的有效性验证。

## 13. 对 EvoLean Lab 流程的评价

本轮实验完成了以下闭环：

1. 从经典极值问题派生饱和版本；
2. 写出精确定义和可计算目标；
3. 生成小规模数据；
4. 从数据提出简洁规律；
5. 主动搜索反例并推翻错误规律；
6. 形成修正后的有限定理候选；
7. 找到显式上界见证；
8. 使用独立算法穷举下界；
9. 使用 Lean 核验可形式化的上界证书；
10. 扩展同义术语进行文献查重；
11. 根据证据强度区分 `VERIFIED`、`COMPUTATIONALLY_VERIFIED` 与 `UNRESOLVED`。

这说明当前流程已经能够产生和筛选非平凡数学命题。最明显的不足不是完全“想不出办法”，而是：

- 文献检索需要更系统的引用网络；
- 计算下界需要 proof-producing 模式；
- 从精确小值迈向一般结构定理仍需要更强的证明策略生成能力。

## 14. 下一步实验

### 14.1 把下界变成 Lean 可检查证书

可以让 Python 输出一份紧凑证书，证明每个大小不超过五的 Sidon 集都至少存在一个可加入元素。Lean 只负责检查证书，而不需要在内核中重新进行低效的盲目搜索。

完成后，整个声明 `s(43)=6` 才能升级为 `VERIFIED`。

### 14.2 继续计算饱和阈值

定义 `M(k)` 为 `k` 元 Sidon 集能够饱和的最长初始区间。当前数据为：

`M(1)=1, M(2)=4, M(3)=10, M(4)=22, M(5)=42`。

接下来可以计算 `M(6)`，并研究：

- `M(k)` 的一般上界；
- 显式构造给出的下界；
- 极值见证是否具有共同的差分结构；
- `M(k)` 是否为新的或已有的整数序列。

### 14.3 建立一般计数界

若 `A` 是大小为 `k` 的极大 Sidon 集，则区间外每个不可加入点都必须被某个加法碰撞阻塞。对阻塞方程分类并计数，应该能够给出 `s(N)` 的立方根量级初等下界。

更值得研究的问题是：Sidon 条件会使这些阻塞表示高度重叠还是近似互异？改进粗糙计数常数可能形成真正的一般定理。

### 14.4 新颖性审计

在任何论文声明之前，需要直接阅读 Ruzsa 的两篇论文及其后续引用，核对：

- 文献使用的“maximal/complete Sidon set”是否与本实验定义完全相同；
- 是否已有 `s(N)` 或等价函数；
- 是否已有小规模表格或一般渐近界；
- 我们的有限值、构造和算法是否提供任何新增内容。
